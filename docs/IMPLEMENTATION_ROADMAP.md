## RFQ — ИҶРО ШУД

Ҳамаи чор қарори нақшашуда татбиқ шуданд:

1. **Версияи пешниҳод нигоҳ дошта мешавад** — `TestRFQQuoteKeepsVersionHistory`
2. **Пешниҳод мӯҳлат дорад** — `TestRFQCannotAwardExpiredQuote`
3. **Қабул фармоиш месозад, нарх аз ПЕШНИҲОД** —
   `TestRFQAwardCreatesOrderWithQuotePrice`
4. **«Шартнома» номида намешавад** — сабти шартҳо ҳаст, даъвои ҳуқуқӣ не

Ва як қоидаи амният, ки дар нақша набуд, вале ҳалкунанда баромад:

    ФУРӮШАНДА ПЕШНИҲОДИ РАҚИБОНАШРО НАМЕБИНАД.

Бе ин тамоми RFQ бефоида аст: фурӯшандаи дуюм нархи аввалро мебинад ва
як дирам камтар мегузорад. Он гоҳ ҳеҷ кас нархи ҳақиқии худро намедиҳад.
Ҳатто шумораи пешниҳодҳо пинҳон аст.

**Камбудии ҷиддӣ, ки ҳангоми ин кор ёфт шуд:** фармоиши RFQ маҳсулоти
мушаххас надорад, вале 11 ҷойи код «моли ин фурӯшанда»-ро бо
`JOIN products` мепурсид — пас сатри бе маҳсулот ГУМ мешуд. Натиҷа:
фармоиши RFQ дар панели фурӯшанда намоён намешуд, ва дар `settleOrder`
фурӯшанда **ПУЛ намегирифт** (0.00 ба ҷои 250.00 — исбот карда шуд).

## P3 — Пардохт: мантиқ ИҶРО ШУД, провайдер мондааст 🔑

### Он чизе, ки ТАЙЁР аст (28 тест)

Се чизи аз ҳама хатарноки пардохт ба провайдер ҳеҷ рабте надоранд, ва
онҳо сохта ва санҷида шудаанд:

| Чӣ | Чаро хатарнок аст | Тест |
|---|---|---|
| Такрори webhook | провайдер ҳамон рӯйдодро чанд бор мефиристад — ин МЕЪЁРИ КОР аст | 10 дархости ҳамзамон → 1 сатр, 1 огоҳӣ |
| Имзо | бе он ҳар кас «пардохт шуд» мефиристад ва моли ройгон мегирад | `hmac.Equal`, на `==` |
| Тартиби ҳолатҳо | рӯйдодҳо бо тартиби вайрон мерасанд | `paid → pending` имконнопазир |
| Ҳисоббаробаркунӣ | webhook метавонад ГУМ шавад | ҳолат аз провайдер пурсида мешавад |

Инчунин: `payment_intents` + `payment_events` бо `UNIQUE` дар БАЗА (на
дар код — ду дархости ҳамзамон санҷиши кодиро ҳарду мегузаранд), ва
провайдери `sandbox`, ки ОШКОРО худашро sandbox меномад.

### Он чизе, ки мондааст

**Як adapter бо чор усул:** `Initiate`, `Status`, `VerifyWebhook`,
`Refund`. Ҳамин.

**Аз шумо лозим:** шартнома бо Алиф ё Корти Миллӣ ва маълумоти merchant.

То он вақт `PAYMENT_PROVIDER` холӣ мемонад ва ҳамаи масирҳои пардохт
**503** медиҳанд. Ин қасдан чунин аст: «провайдери қалбакӣ, ки ҳамеша
мегӯяд пардохт шуд» дар production моли ройгон медод.

Роҳи ҳозира (расми чек + тасдиқи дастии фурӯшанда) кор мекунад ва дар
ҳеҷ санад «пардохти онлайн» номида намешавад.

## P4 — Он чизҳое, ки ман дидаву дониста НАКАРДАМ

Рӯирост, бо сабаб:

### Пардохти алоҳидаи ҳар фурӯшанда
Ҳоло пул як бор, баъди супоридани охирин мол озод мешавад. Беҳтар
мебуд, ки ҳар фурӯшанда ҳамин ки худаш супорид, пулашро гирад.

**Чаро накардам:** `settleOrder` хатарноктарин коди барнома аст. Хато дар
он ё пули дукарата медиҳад, ё пулро гум мекунад. Ин ислоҳи
«коррект-кунӣ» нест — ин беҳтаркунӣ аст, ва он сазовори коммити
ҷудогона бо тестҳои худаш аст.

### Ҷустуҷӯи `tsvector` — ва чаро ба ҷояш pg_trgm шуд

Дар санади аввал ман навишта будам: «пеш аз беҳтаркунӣ бояд АНДОЗА
ГИРИФТ». Андоза гирифтам — 60 000 маҳсулоти воқеӣ, `EXPLAIN ANALYZE`:

    БЕ индекс:   99 мс, Seq Scan, 51 429 сатр партофта шуд
    БО pg_trgm:  12 мс, Bitmap Index Scan        → 8 баробар

Яъне масъала воқеӣ буд, на тахминӣ. Пас сохта шуд.

Вале НЕ бо `tsvector`, чунон ки аввал нақша буд. Сабаб: `tsvector`
калимаи ПУРРА меҷӯяд. Корбар «Samsu» менависад ва «Samsung»-ро интизор
аст — `tsvector` онро НАМЕЁБАД, триграм меёбад (14.5 мс,
андозагирифташуда).

Ва бо триграм дархост ТАҒЙИР НАМЕЁБАД — танҳо индекс илова мешавад.
`tsvector` бознависии дархост ва тағйири маънои ҷустуҷӯро талаб мекард.

Ин мисоли он аст, ки чаро андозагирӣ пеш аз қарор меистад: он на танҳо
«оё лозим аст?» мегӯяд, балки «КАДОМ роҳ?» ҳам.

### 50+ хусусияти нав
Шумо 50+ хусусият хостед. Ман 50 хусусияти нимкора намесозам — маҳз
ҳамон чизро мо тамоми ин сессия ислоҳ кардем: хусусияте, ки экран дорад,
вале кор намекунад (`wholesale_price` мисоли мустақим аст — як рақам буд,
ки ҳеҷ ҷо истифода намешуд).

Ба ҷояш аз рӯйхат чизҳое интихоб мешаванд, ки САБАБИ ТИҶОРАТӢ доранд:
- каталоги умумии штрих-код (мағозаи хӯрокворӣ) — иҷро шуд
- мӯҳлати нигоҳдорӣ — иҷро шуд
- зинаҳои нархи яклухт — иҷро шуд
- RFQ — қадами навбатӣ

### Микросервис, Kubernetes, Kafka
Дар ин андоза онҳо зарар мерасонанд, на фоида. Monolith-и хуб сохташуда

### Хатоҳои ХУДИ МАН дар ин сессия

Онҳо низ сабт мешаванд — вагарна санад нопурра аст:

1. `MissingPluginException` бе import → билди release афтод
2. Backtick дар шарҳи SQL — **се бор**. Ҳал: схема ба файли `.sql`
3. Нуқтавергул дар шарҳи SQL → индекс сохта нашуд (тести худам онро дошт)
4. Хатои off-by-one дар ислоҳи №3 (`i+1 < len(line)`) → тести худам боз дошт
5. `DATABASE_URL` ба ҷои `DB_URL` → `env_check.py` онро дошт
6. Overflow-и 194 пиксел аз иловаи ду тугма → тести эмулятор онро дошт
7. `callList` барои масире, ки объект бармегардонад → 5 тест афтод

Дар ҳар ҳолат камбудӣ то production НАРАСИД, чунки санҷиш буд. Ин
худаш далели он аст, ки санҷишҳо кор мекунанд.
