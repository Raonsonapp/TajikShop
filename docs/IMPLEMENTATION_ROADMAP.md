## Қадами навбатӣ: P2 — RFQ

Ин аз ҳама чизи муҳими боқимонда аст. Alibaba.com бе он Alibaba нест:
харидор дархости таъминот мегузорад, фурӯшандагон пешниҳод медиҳанд,
гуфтушунид мешавад, пешниҳоди қабулшуда ба фармоиш табдил меёбад.

### Нақшаи база

```sql
rfqs (
  id, buyer_id, title, description, category_id,
  quantity, unit, target_price, destination,
  needed_by DATE, closes_at TIMESTAMPTZ,
  status,            -- open | closed | awarded | cancelled
  created_at
)
rfq_attachments (id, rfq_id, url)
rfq_quotes (
  id, rfq_id, seller_id, version,
  unit_price, min_qty, shipping_cost, lead_days,
  valid_until, payment_terms, note,
  status,            -- submitted | revised | withdrawn | accepted | rejected
  created_at
)
rfq_messages (id, rfq_id, sender_id, body, created_at)
```

### Қарорҳои муҳим, ки ҳоло қабул шудаанд

**1. Версияи пешниҳод нигоҳ дошта мешавад, иваз намешавад.**
Фурӯшанда пешниҳодро тағйир медиҳад → сатри НАВ бо `version+1`, кӯҳна
`status='revised'` мешавад. Бе ин харидор метавонад нархи дидаашро исбот
карда натавонад — ва ин маҳз он ҷоест, ки ихтилоф ба вуҷуд меояд.

**2. Пешниҳод мӯҳлат дорад (`valid_until`).**
Бе он фурӯшанда абадӣ ба нархи шашмоҳа пешниҳодкардааш баста мемонад.

**3. Қабули пешниҳод фармоиш месозад, вале НАРХ АЗ ПЕШНИҲОД мегирад.**
Ин бо checkout-и ҳозира мувофиқ меояд: ҳамон транзаксия, ҳамон санҷиши
анбор, вале `UnitPrice` аз `rfq_quotes`, на аз `products.price`.

**4. «Шартнома» номида намешавад.**
Паёми чат шартномаи ҳуқуқӣ нест. Сабти «шартҳои мувофиқашуда» сохта
мешавад (нарх, шумора, мӯҳлат, шартҳои пардохт, тасдиқи ҳарду тараф бо
вақт), вале он ҳамчун санади ҳуқуқӣ пешниҳод намешавад — то касе ба он
такя накунад.

### Тартиби кор
1. Migration + `rfq.go` бо мантиқи тозаи санҷидашаванда
2. Тестҳои база: иҷозат, мӯҳлат, версия, қабул → фармоиш
3. Экранҳо: «Дархости ман», «Дархостҳои кушода» (фурӯшанда), пешниҳод,
   муқоиса
4. tg/ru/en

## P3 — Пардохти воқеӣ 🔑

**Баста ба маълумоти берунӣ.** Ман провайдер эҷод намекунам ва калиди
бофта намегузорам.

Он чизе, ки ҳоло тайёр карда мешавад:
- интерфейси `PaymentProvider` (initiate / status / webhook / refund)
- adapter-и sandbox барои тест
- санҷиши имзои webhook + idempotency аз рӯи `event_id`
- дафтари амалиёт бо сатрҳои пайгиришаванда

**Аз шумо лозим:** шартнома бо Алиф ё Корти Миллӣ ва маълумоти merchant.
То он вақт роҳи ҳозира (расми чек + тасдиқи фурӯшанда) мемонад ва дар
ҳеҷ санад «пардохти онлайн» номида намешавад.

## P4 — Он чизҳое, ки ман дидаву дониста НАКАРДАМ

Рӯирост, бо сабаб:

### Пардохти алоҳидаи ҳар фурӯшанда
Ҳоло пул як бор, баъди супоридани охирин мол озод мешавад. Беҳтар
мебуд, ки ҳар фурӯшанда ҳамин ки худаш супорид, пулашро гирад.

**Чаро накардам:** `settleOrder` хатарноктарин коди барнома аст. Хато дар
он ё пули дукарата медиҳад, ё пулро гум мекунад. Ин ислоҳи
«коррект-кунӣ» нест — ин беҳтаркунӣ аст, ва он сазовори коммити
ҷудогона бо тестҳои худаш аст.

### Ҷустуҷӯи `tsvector`
`ILIKE '%...%'` индекс истифода намебарад. Дар 50k маҳсулот суст мешавад.

**Чаро накардам:** ҳоло маҳсулот кам аст ва ҳеҷ зараре надорад. Пеш аз
беҳтаркунӣ бояд АНДОЗА ГИРИФТ — вагарна мо чизе беҳтар мекунем, ки
масъала нест. Дар санади аудит ҳамчун «миёна» навишта шуд.

### 50+ хусусияти нав
Шумо 50+ хусусият хостед. Ман 50 хусусияти нимкора намесозам — маҳз
ҳамон чизро мо тамоми ин сессия ислоҳ кардем: хусусияте, ки экран дорад,
вале кор намекунад (`wholesale_price` мисоли мустақим аст — як рақам буд,
ки ҳеҷ ҷо истифода намешуд).

Ба ҷояш аз рӯйхат чизҳое интихоб мешаванд, ки САБАБИ ТИҶОРАТӢ доранд:
- каталоги умумии штрих-код (мағозаи хӯрокворӣ) — иҷро шуд
- мӯҳлати нигоҳдорӣ — иҷро шуд
- зинаҳои нархи яклухт — иҷро шуд
- RFQ — қадами навбатӣ

### Микросервис, Kubernetes, Kafka
Дар ин андоза онҳо зарар мерасонанд, на фоида. Monolith-и хуб сохташуда
то он лаҳза мемонад, ки воқеан deploy-и ҷудогона лозим шавад.
