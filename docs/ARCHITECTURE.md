### Қоидаи ҷудокунӣ, ки дар ин сессия ҷорӣ шуд

**Мантиқи ҳисоб аз база ҷудо карда мешавад.**

Пештар ҳамаи ҳисоб дар дохили handler буд, бо `db.DB` дар миёна. Чунин
кодро санҷидан номумкин аст — барои ҳар санҷиш база лозим мешавад.

Ҳоло:

```
money.go           ҳисоби пул, санҷиши сатрҳои сабад   → БЕ база
price_tiers.go     `priceForQty`, `validateTiers`      → БЕ база
order_status.go    `aggregateOrderStatus`              → БЕ база
checkout.go        танҳо транзаксия ва дархостҳо
```

Натиҷа: 37 тест БЕ база иҷро мешаванд (зуд, дар ҳар машин), ва 24 тест
бо Postgres-и воқеӣ — он ҷое, ки воқеан база лозим аст (қулф,
транзаксия, `UNIQUE`, дархостҳои ҳамзамон).

### Қарори пул: дирами бутун

```go
toDirams(19.99) == 1999      // int64
```

`float64` барои пул мувофиқ нест: `0.1+0.2` дар он
`0.30000000000000004` мешавад. Дар савдо ин маънои онро дорад, ки ҷамъи
сабад ва ҷамъи фармоиш бо як дирам фарқ мекунанд — харидор дар экран як
рақам мебинад, вале аз ҳамёнаш рақами дигар меравад.

Пас: аз `NUMERIC(12,2)` мехонем → фавран ба дирам → ҳамаи ҳисоб дар
бутун → танҳо дар сарҳади база ва JSON ба сомонӣ бармегардонем.

### Транзаксия: куҷо ва чаро

| Ҷой | Чӣ қулф мешавад | Чаро |
|---|---|---|
| `Checkout` | `products` бо `FOR UPDATE OF p`, `ORDER BY product_id` | фурӯши зиёдатӣ |
| `Checkout` | `users.wallet_balance` бо `FOR UPDATE` | пули дукарата |
| `Checkout` | `coupons` бо `FOR UPDATE` | купони такрорӣ |
| `SellerUpdateOrderStatus` | `order_sellers` бо `FOR UPDATE` | қадами дукарата |
| `SetTiers` | — (DELETE+INSERT дар як tx) | ҳолати нимкора |
| `settleOrder` | `orders` бо шарти ҳолат | пардохти дукарата |

`ORDER BY ci.product_id` дар checkout ҲАТМИСТ. Бе он ду харидор, ки
ҳамон молҳоро бо тартиби гуногун мефармоянд, якдигарро қулф мекунанд
(deadlock). Бо тартиби муайян ҳарду ҳамон молро аввал мегиранд.

### Idempotency

```
POST /orders/checkout
Idempotency-Key: co-<вақт>-<тасодуфӣ>
```

Калид дар ҲАМОН транзаксия бо фармоиш сабт мешавад (`checkout_keys`,
`PRIMARY KEY`). Пас ду дархости ҳамзамон имконнопазир аст: дуюмаш ба
`UNIQUE` бархӯрд мекунад ва тамоми транзаксияаш бекор мешавад.

Дар барнома калид ЯК бор барои ҳар кӯшиш сохта мешавад ва танҳо баъди
фармоиши муваффақ нав мешавад. Агар он дар ҳар зеркунӣ нав шавад, тамоми
муҳофизат маъно надорад.

## 3. Фармоиши бисёрфурӯшанда

Ин ҷои аз ҳама нозуки меъморӣ аст.

```
orders            ← як сатр, `status` ҲИСОБШУДА
  └─ order_sellers  ← як сатр барои ҳар фурӯшанда, `status`-и ХУДАШ
       └─ order_items (`seller_id` сурат)
```

`orders.status` боқӣ монд, на нест шуд: тамоми барнома, админка,
огоҳиҳо ва ҳисоботҳо онро мехонанд. Иваз кардани ҳамаи он якбора хатари
хеле калон буд. Пас он мемонад, вале **ҳисобшуда** аст:

```go
aggregateOrderStatus([]string{"shipped", "processing"}) == "processing"
```

Камтарин дараҷа дар байни фурӯшандагони бекорнакарда. Яъне фармоиш
«фиристода шуд» нест, то ҳар фурӯшанда нафиристад.

Вақтҳо (`shipped_at`, `delivered_at`, `protect_until`) танҳо вақте
гузошта мешаванд, ки ҲАМА ба он қадам расанд. Ин муҳим аст: мӯҳлати
шикояти харидор бояд аз лаҳзаи супоридани ОХИРИН мол сар шавад, вагарна
ӯ метавонад мӯҳлатро барои моли нагирифта гум кунад.

## 4. Нархи яклухт

Манбаи ягонаи ҳақиқат — сервер:

```
GET /cart          → `price` аллакай нархи зина
POST /orders/checkout → ҳамон `priceForQty`
```

Барнома ҳисоби худашро **надорад** — он нархи омадаро нишон медиҳад.
Агар барнома ҳисоби худашро медошт, рӯзе ду ҳисоб аз ҳам фарқ мекард.

Тест `TestCartAndCheckoutAgreeOnTierPrice` маҳз ҳаминро муҳофизат
мекунад: нархи сабад × шумора бояд ба ҷамъи checkout баробар бошад.

## 5. Flutter

```
lib/
├── core/
│   ├── api/          dio, interceptor-ҳо, нав кардани токен
│   ├── l10n/         11 extension (tg/ru/en)
│   └── theme/        `context.pal.*` — ҳар ранг аз ҷадвал
├── data/             моделҳо, repository
├── modules/          22 модул аз рӯи экран
├── providers/        Riverpod
└── shared/widgets/
```

### Се қоидаи ҳатмӣ

**1. Тарҷума дар extension, на дар экран.**
`order_timeline.dart` танҳо тоҷикӣ буд — матнҳо сахт навишта шуда буданд.
Корбари русзабон дар экрани фармоиши худаш матни тоҷикӣ мебинад. Ҳоло
ҳар матни нав ба `core/l10n/*.dart` меравад ва тест ҳамаи се забонро
месанҷад.

**2. Ҳар ранг аз `context.pal`.**
Вагарна дар режими торик матни сиёҳ дар фони сиёҳ мемонад.

**3. Localization-и Material барои тоҷикӣ.**
Тоҷикӣ дар `flutter_localizations` **нест**. Бе
`fallback_localizations.dart` ҳамаи `showModalBottomSheet`,
`RefreshIndicator` ва тугмаи бозгашт дар release ба **росткунҷаи
хокистарранг** табдил меёфтанд. Маҳз ҳамин камбудӣ сабаби «тугма кор
намекунад» буд, ки шумо нишон дода будед.

### Чаро `backend_test.yml` лозим буд

`db.Migrate()` → `execEach` ҳар амрро ҷудогона иҷро мекунад ва хатои
ҳар якро **ба лог менависад ва мегузарад**:

```go
if _, err := DB.Exec(s); err != nil {
    log.Printf("⚠️  migration stmt skipped: %v", err)
}
```

Ин барои сервер хуб аст (як амри вайрон login-ро намешиканад), вале
хатарнок: амри вайрон дар production ХОМӮШОНА ҳеҷ кор намекунад ва то
рӯзи аввалин фармоиш маълум намешавад.

Пас дар CI migration дар базаи ТОЗА иҷро мешавад. Агар ягон амр афтад,
тестҳои он ҷадвал меафтанд.

### Муҳофизи маҳаллӣ: `tools/import_guard.py`

`dart format` танҳо **синтаксис**-ро месанҷад. Номи номуайян онро
мегузарад — ва маҳз чунин хато (`MissingPluginException` бе import)
билди release-ро шикаст.

Муҳофиз 150 файлро мегардад (`lib/`, `test/`, `integration_test/`) ва
месанҷад:
- `xProvider` бе import
- `l.<name>`-и l10n бе import-и extension
- номҳое, ки `services.dart`, `dart:math`, `dart:convert`, `dart:io`,
  `dart:async` талаб мекунанд

Он воқеан санҷида шуд: сатри import бароварда → `problems=1`,
баргардонда → тоза.

## 8. Он чизе, ки андоза гирифта НАШУДААСТ

Рӯирост:

- **Бори вазнин** — ман ба базаи production бор надодам. Пас ягон рақами
  «барнома N корбарро мебардорад» дар ҳеҷ санад нест.
- **Нақшаи дархостҳо (`EXPLAIN`)** — дар базаи воқеӣ бо маълумоти воқеӣ
  санҷида нашуд.
- Маълум аст, ки ҷустуҷӯи `ILIKE '%...%'` индекс истифода намебарад — ин
  аз худи дархост маълум, на аз андозагирӣ.
