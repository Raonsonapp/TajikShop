**Сана:** 13.10.2026
**Коммити санҷидашуда:** `a1768b6` (`main`)
**Шоха:** `claude/alibaba-performance-optimization-ra8yg7`

Ин санад бо хондани файлҳои ВОҚЕӢ навишта шудааст, на аз рӯи тахмин. Ҳар
камбудӣ бо `файл:сатр` нишон дода шудааст ва он ҷое, ки тест навишта шуд,
тест ҳам оварда мешавад. Он ҷое, ки ман иҷро карда натавонистам, рӯирост
навишта шудааст.

## 2. Камбудиҳои дарёфтшуда

### P0-1 · Фурӯши зиёдатӣ — анбор ТАМОМАН санҷида намешуд

**Ҷой:** `backend/internal/handles/order_handler.go` (нусхаи кӯҳна,
сатри ~205 ва ~246)

```go
db.DB.Exec(`UPDATE products SET stock=GREATEST(stock-$1,0) WHERE id=$2`,
    i.Qty, i.ProductID)
```

`GREATEST(...,0)` ҳар шуморро қабул мекунад. Дар анбор 3 дона буд,
харидор 100 дона мефармуд — фармоиш қабул мешуд, анбор 0 мешуд, ва
фурӯшанда бо харидор рӯ ба рӯ мемонд.

**Исботи воқеӣ.** Тести `TestCheckoutConcurrentLastItem` навишта шуд: 1
дона дар анбор, 8 харидори ҳамзамон. Бо муҳофизат бароварда:

```
3 фармоиш гузашт, мехостам ТАНҲО 1. Ҳолатҳо: [409 201 409 201 409 409 409 201]
```

Яъне **як мол ба се нафар фурӯхта шуд**.

**Ҳал:** `backend/internal/handles/checkout.go` — `FOR UPDATE OF p` бо
`ORDER BY ci.product_id` (тартиби муайян, то deadlock нашавад) +
`validateLines()` + шарти `WHERE stock >= $1` ҳамчун муҳофизати дуюм.
**Ҳолат:** ислоҳ шуд, бо тест.

### P0-2 · Роҳи ғайри-ҳамён транзаксия надошт

**Ҷой:** ҳамон ҷо, сатри ~240–260.

Сохтани фармоиш, молҳо, кам кардани анбор ва тоза кардани сабад чор
амри ҶУДОГОНАИ `db.DB.Exec` буданд. Агар сервер дар байни онҳо афтад
(HF Space ҳар рӯз аз нав оғоз мешавад), фармоиши бе мол ё анбори
камшудаи бе фармоиш мемонд.

**Ҳал:** ҳамааш дар як `tx`. Тест: `TestCheckoutFailureLeavesNothing` —
фармоиши радшуда на сатр мегузорад, на анборро кам мекунад, на сабадро
тоза мекунад.
**Ҳолат:** ислоҳ шуд, бо тест.

### P0-3 · Idempotency набуд — ду фармоиш аз як зеркунӣ

**Ҷой:** `order_handler.go` + `lib/modules/cart/cart_screen.dart:_submit`

Калиди idempotency умуман набуд. Ду зеркунии тугма ё такрори шабака ДУ
фармоиш месохт — ва барои пардохти ҳамён **ду бор пул** мерафт.

**Ҳал:** ҷадвали `checkout_keys` + сарлавҳаи `Idempotency-Key`. Калид
дар дохили ҳамон транзаксия сабт мешавад, пас ду дархости ҳамзамон
имконнопазир аст. Дар барнома калид ЯК бор барои ҳар кӯшиш сохта
мешавад ва танҳо баъди фармоиши муваффақ нав мешавад.
Тестҳо: `TestCheckoutIdempotency`, `TestCheckoutIdempotencyConcurrent`
(8 дархости ҳамзамон бо ҳамон калид → 1 фармоиш).
**Ҳолат:** ислоҳ шуд, бо тест.

### P0-4 · Пули расонидан аз муштарӣ меомад

**Ҷой:** `order_handler.go:118-131`

```go
deliveryFee := in.DeliveryFee          // аз JSON-и муштарӣ
if deliveryFee > maxDeliveryFee { deliveryFee = maxDeliveryFee }
```

Танҳо ҳадди БОЛО маҳдуд буд. `{"delivery_fee": 0}` расониданро ройгон
мекард.

**Ҳал:** `deliveryFeeFor(fulfilment)` дар сервер. Рақами муштарӣ умуман
хонда намешавад. Тест: `TestCheckoutIgnoresClientDeliveryFee`.
**Ҳолат:** ислоҳ шуд, бо тест.

### P0-5 · Купон бемаҳдуд такрор мешуд

**Ҷой:** `backend/internal/handles/wallet_handler.go:148` (`lookupCoupon`)

Танҳо `used_count`-и УМУМӢ санҷида мешуд. Як корбар метавонист ҳамон
купонро бефосила истифода кунад.

**Ҳал:** `coupons.per_user_limit` + ҷадвали `coupon_redemptions`, санҷиш
дар дохили транзаксия бо `FOR UPDATE`. Тест:
`TestCheckoutCouponOncePerUser`.
**Ҳолат:** ислоҳ шуд, бо тест.

### P0-6 · Сабад ҳеҷ санҷиш надошт

**Ҷой:** `order_handler.go:58-76` (`AddToCart`), `86-103` (`UpdateCartItem`)

`AddToCart` фавран `INSERT` мекард: моли нестро, моли хомӯшро, моли
тамомшударо ва `{"quantity": 2000000000}`-ро қабул мекард. Хато танҳо
дар лаҳзаи пардохт пайдо мешуд.

**Ҳал:** санҷиши вуҷуд/фаъолият/анбор/ҳадди ақал, маҳдудияти `maxLineQty`,
ва манъи харидани моли ХУДИ фурӯшанда (вагарна ҳисоби фурӯш вайрон
мешавад). Тестҳо: `TestCheckoutEnforcesMinOrderQty`,
`TestCheckoutSellerCannotBuyOwnProduct`, `TestCheckoutRejectsMoreThanStock`.
**Ҳолат:** ислоҳ шуд, бо тест.

### P0-7 · Пул бо `float64` ҳисоб мешуд

**Ҷой:** тамоми `order_handler.go`

`float64` рақами даҳиро дақиқ нигоҳ намедорад: `0.1+0.2` дар он
`0.30000000000000004` мешавад. Дар савдо ин маънои онро дорад, ки ҷамъи
сабад ва ҷамъи фармоиш бо як дирам фарқ мекунанд — харидор дар экран як
рақам мебинад, вале аз ҳамёнаш рақами дигар меравад.

**Ҳал:** `backend/internal/handles/money.go` — ҳамаи ҳисоб бо дирами
бутун (`int64`), табдил танҳо дар сарҳади база. Тестҳо: `TestToDirams`,
`TestNoFloatDrift`, `TestDiscountRounding`.
**Ҳолат:** ислоҳ шуд, бо тест.

### P0-8 · Хатои `rows.Scan` ва `Exec` партофта мешуд

**Ҷой:** даҳҳо ҷой; дар checkout — `order_handler.go:152`

```go
rows.Scan(&i.ProductID, &i.Qty, &i.Price)   // хато хонда намешавад
```

Агар сутуни `NULL` ба `string` афтад, `Scan` хато медиҳад ва тамоми сатр
СИФР мемонад — он гоҳ маҳсулот бо нархи 0 ба фармоиш мегузашт. Маҳз
ҳамин камбудӣ пештар дар рӯйхати маҳсулот «0 сом. / Тамом шуд» месохт.

**Ҳал:** дар `checkout.go` ҳар `Scan` ва ҳар `Exec` санҷида мешавад.
**Ҳолат:** дар роҳи checkout ислоҳ шуд. Дар дигар handler-ҳо ҳанӯз
мондааст — ба roadmap гузошта шуд (P1).

### P0-9 · `utils.UserID` метавонист серверро партояд

**Ҷой:** `backend/internal/utils/utils.go:31`

```go
id, _ := c.Get("user_id")
return id.(string)        // nil → panic
```

Агар масире тасодуфан бе middleware-и аутентификатсия сабт шавад, ин
тамоми серверро мепартояд, на танҳо он дархостро.

**Ҳал:** санҷиши навъ, баргардонидани сатри холӣ.
**Ҳолат:** ислоҳ шуд.

### P1-1 · Фармоиши бисёрфурӯшанда — як ҳолат барои ҳама

**Ҷой:** `backend/internal/handles/buyer_protection.go:78-140`

`SellerUpdateOrderStatus` соҳибиятро месанҷад («фармоиш моли ман
дорад?»), вале баъд `UPDATE orders SET status=...` — яъне ҲОЛАТИ ТАМОМИ
ФАРМОИШро иваз мекунад.

Дар сабад моли ду фурӯшанда буд. Фурӯшандаи A «фиристодам» мезад — ва
моли нафиристодаи фурӯшандаи B ҳам «фиристода шуд» мешуд. Ҳимояи
харидор (`protect_until`) барои ҳар ду сар мешуд, яъне мӯҳлати шикоят
барои моли ҳанӯз нафиристода мегузашт.

**Ҳал (қисман):** ҷадвали `order_sellers` сохта шуд ва checkout
зер-фармоишҳоро месозад. Тест: `TestCheckoutSplitsPerSeller`.
**Ҳолат:** база ва сохтани фармоиш тайёр; `SellerUpdateOrderStatus`
ҳанӯз ба зер-фармоиш нагузаштааст → P1 дар roadmap.

### P1-2 · `order_items` сурати маҳсулот надошт

**Ҷой:** `backend/internal/db/postgres.go` — ҷадвали `order_items`

Танҳо `product_id` ва нарх буд. Агар фурӯшанда баъд номи маҳсулотро
иваз кунад, таърихи фармоиши кӯҳна ҳам иваз мешуд — харидор дар фармоиши
дусолаи худ номи дигарро мебинад.

**Ҳал:** `seller_id`, `title`, `unit` ҳамчун сурат илова шуданд, ва
сатрҳои кӯҳна як бор пур карда шуданд.
**Ҳолат:** ислоҳ шуд.

### P2-1 · Нархи яклухт зина надорад

**Ҷой:** `products.wholesale_price` — ЯК рақам.

Alibaba бо зинаҳо кор мекунад (1–9 чакана, 10–49 яклухт, 50+ гуфтушунид).
Ҳоло ин имкон нест.
**Ҳолат:** НЕСТ → P2.

### P2-2 · RFQ (дархости нарх) тамоман нест

Ин маркази Alibaba.com аст: харидор дархости таъминот мегузорад,
фурӯшандагон пешниҳод медиҳанд, гуфтушунид мешавад, пешниҳоди
қабулшуда ба фармоиш табдил меёбад. Дар анбор ягон сатри ин нест.
**Ҳолат:** НЕСТ → P2.

## 4. Он чизе, ки ман ИҶРО КАРДА НАТАВОНИСТАМ

Рӯирост, то дар санад даъвои бардурӯғ намонад:

- **`flutter analyze` ва `flutter test`** — Flutter SDK дар ин муҳит
  нест. Ба ҷояш: парси ҳамаи 145 файли Dart бо `dart format` ва
  муҳофизи `tools/import_guard.py`. Таҳлили пурра дар CI мегузарад.
- **Билди APK** — танҳо дар CI.
- **Тести бори вазнин (load test)** — база дар HF/Supabase аст, ман ба
  он бор надодам. Пас ягон рақами «барнома N корбарро мебардорад» дар
  ин санад нест.
- **Пардохти воқеӣ** — бе маълумоти merchant-и Алиф/Корти Миллӣ
  санҷидан номумкин аст.
